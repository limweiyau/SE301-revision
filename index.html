02 / Core section

Aggregation vs composition

Both are “has-a” whole-part relationships. The difference is how strongly the whole owns its parts.

Aggregation

Parts stay independent

Aggregation is a “has-a” relationship where parts can exist independently, outlive the whole, and be shared.

UML places a hollow diamond on the whole side.

Composition

The whole owns the lifetime

Composition is a “has-a” relationship where parts cannot exist without the whole.

The whole owns their lifetimes, so deleting it deletes its parts; UML uses a filled diamond.

Compare Aggregation Composition
Lifetime Parts can outlive the whole. The whole owns part lifetimes.
Sharing A part may be shared. A part belongs to one whole at a time.
Delete whole Parts can remain. Parts are deleted too.
UML Hollow diamond. Filled diamond.
03 / Singleton

Singleton — one instance only

A Singleton provides one shared instance when an application needs a single point of access.

Singleton

Java 
public class Singleton {
  private static final Singleton INSTANCE =
      new Singleton();
  private Singleton() {}
  public static Singleton getInstance() {
    return INSTANCE;
  }
}
04 / Tiny code examples

See ownership in Java

Look at where each part is created. That choice signals the intended lifetime.
If a class declares no constructor, Java inserts a default one.

Aggregation

Java 
import java.util.List;

final class Book { }

final class Library {
  private final List<Book> books;
  Library(List<Book> books) {
    this.books = books;
  }
}

The books are created elsewhere and passed into the library.

Composition

Java 
import java.util.List;

record Room(String name) { }

final class House {
  private final List<Room> rooms;
  House() {
    rooms = List.of(new Room("Kitchen"),
                    new Room("Bedroom"));
  }
}

The house creates its rooms and controls their lifetime.

Constructor chaining
default constructors

Java 
class Grandparent { }                              // implicit default constructor: Grandparent() { super(); }
class Parent extends Grandparent { }               // implicit: Parent() { super(); } -> chains up to Grandparent
final class Child extends Parent {
  Child() { super(); }                             // explicit, writes the chain by hand
  // if omitted, javac inserts this exact super() call
}

Constructors chain vertically up the hierarchy: Child -> Parent -> Grandparent -> Object. A default constructor appears when none is declared.

05 / UML quick reference

Read the line endings

Start at the symbol, then identify which class it touches.

Association

A general class relationship; ownership is not implied.

Aggregation

Independent parts; hollow diamond at the whole.

Composition

Lifetime-owned parts; filled diamond at the whole.

Inheritance

An “is-a” link; open triangle points to the superclass.

1Exactly one.
1..*One or more.
0..*Zero or more.
06 / Self-check

Can you answer these?

Choose a question to reveal its answer.

Can an aggregated part outlive its whole?

Answer: Yes. It can exist independently.

What happens to composed parts when the whole is deleted?

Answer: The parts are deleted with it.

Which diamond represents composition?

Answer: A filled diamond on the whole side.

What does 1..* mean?

Answer: One or more instances.

How do you obtain the singleton instance?

Answer: Through getInstance(); the constructor is private.
